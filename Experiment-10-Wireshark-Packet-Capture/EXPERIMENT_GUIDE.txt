2. AIM
--------------------------------------------------------------------------------
To capture live network traffic using the Wireshark packet analyzer, formulate Berkeley Packet Filter (BPF) capture filters and Wireshark display filters to isolate traffic to/from a target host (such as Facebook / web endpoints), analyze the TCP 3-way handshake, inspect TCP control flags (SYN, PSH, RST), compute traffic fraction statistics, and explain TLS/HTTPS encryption realities.

3. REQUIREMENTS
--------------------------------------------------------------------------------
Hardware Requirements:
- Computer (PC/Laptop) running Linux (Ubuntu), macOS, or Windows with an active Network Interface Card (Ethernet or 802.11 Wi-Fi) connected to the Internet.

Software Requirements:
- Wireshark Network Protocol Analyzer (version 3.x or 4.x).
- Packet capture library: `libpcap` on Linux/macOS or `Npcap` on Windows.
- Standard Web Browser (Google Chrome, Mozilla Firefox, Safari) to generate live network traffic.
- Command-line diagnostic tools: `nslookup`, `dig`, or `ping` to resolve target host IP addresses.
- Administrative / Root privileges to capture on raw network interfaces (`sudo usermod -aG wireshark $USER` on Linux).

4. LEARNING OBJECTIVES
--------------------------------------------------------------------------------
- Master packet capture mechanics on active network interfaces using Wireshark and underlying capture drivers.
- Distinguish fundamentally between Capture Filters (pre-capture BPF filters) and Display Filters (post-capture analysis filters).
- Analyze the TCP 3-way handshake (SYN -> SYN-ACK -> ACK) and 4-way connection teardown (FIN-ACK).
- Filter and quantify TCP control flags:
  * SYN (`tcp.flags.syn == 1`): Connection synchronization.
  * PSH (`tcp.flags.push == 1`): Data push buffer flush.
  * RST (`tcp.flags.reset == 1`): Abrupt connection abort.
- Compute traffic volume fractions: ratio of HTTP/HTTPS traffic and specific flag occurrences relative to total TCP conversations.
- Understand the security implications of TLS 1.3 / HTTPS: recognize why modern web traffic payloads are encrypted ciphertext and why metadata (IPs, ports, TLS SNI, flag bits) remains visible.

5. THEORY AND IMPORTANT TERMINOLOGY
--------------------------------------------------------------------------------
- Wireshark: A free, open-source packet analyzer used for network troubleshooting, analysis, software and communications protocol development, and education.
- Capture Filters vs. Display Filters:
  * Capture Filters (Berkeley Packet Filter - BPF syntax):
    - Evaluated in the kernel packet capture engine *before* packets are recorded to disk or memory.
    - Non-matching packets are discarded immediately, saving CPU and storage during large-scale network captures.
    - Syntax: BPF format, e.g., `host 157.240.0.35`, `tcp port 443`, `net 192.168.1.0/24`.
    - Cannot be modified while capture is actively running.
  * Display Filters (Wireshark syntax):
    - Applied in the Wireshark application GUI *after* packets have been recorded.
    - Non-matching packets are temporarily hidden from view but remain safely stored in the `.pcapng` capture file.
    - Syntax: Rich protocol relational expressions, e.g., `http`, `tls`, `tcp.flags.syn == 1`, `ip.addr == 157.240.0.35`.
    - Can be modified dynamically without stopping the capture.
- TCP Header Control Flags (6 core 1-bit flags):
  1. SYN (Synchronize): Set during the initial connection request to synchronize sequence numbers.
  2. ACK (Acknowledgment): Confirms receipt of previously transmitted bytes.
  3. PSH (Push): Instructs the receiving TCP stack to immediately deliver buffered data to the application layer rather than waiting for buffers to fill.
  4. RST (Reset): Forcefully and abruptly resets an invalid, unauthenticated, or rejected connection.
  5. FIN (Finish): Indicates that the sender has finished transmitting data and requests connection closure.
  6. URG (Urgent): Points to high-priority urgent data.
- The HTTPS / TLS Reality (Crucial Concept):
  * The lab manual refers to capturing "TCP/HTTP traffic to Facebook".
  * Real-world reality: Facebook (Meta) and almost all modern websites enforce HTTPS (HTTP over TLS, TCP port 443) using HTTP Strict Transport Security (HSTS).
  * Consequently, Wireshark captures TCP handshakes, TLS Client/Server Hellos (exposing the SNI domain name `facebook.com`), and encrypted `Application Data` segments.
  * Plaintext HTTP GET requests, passwords, and HTML content are encrypted by AES-GCM or ChaCha20-Poly1305 and CANNOT be viewed as readable text without the client's ephemeral TLS session keys (`SSLKEYLOGFILE`).

6. NETWORK PACKET FLOW AND TCP 3-WAY HANDSHAKE
--------------------------------------------------------------------------------
TCP Connection Setup, Data Transfer, and Termination:

```
  Client (Browser)                                    Server (e.g. Facebook)
     |                                                          |
     |--------- Segment 1: [SYN] Seq=0 ------------------------>| (SYN=1, ACK=0)
     |                                                          |
     |<-------- Segment 2: [SYN, ACK] Seq=0, Ack=1 ------------| (SYN=1, ACK=1)
     |                                                          |
     |--------- Segment 3: [ACK] Seq=1, Ack=1 ----------------->| (SYN=0, ACK=1)
     |                                                          |
     |  [ 3-Way Handshake Established - Socket State: ESTABLISHED ]
     |                                                          |
     |--------- Segment 4: [PSH, ACK] TLS Client Hello -------->| (PSH=1, ACK=1)
     |                                                          |
     |<-------- Segment 5: [PSH, ACK] TLS Server Hello --------| (PSH=1, ACK=1)
     |                                                          |
     |--------- Segment 6: [PSH, ACK] Encrypted App Data ------>|
     |                                                          |
     |--- (Abrupt port refusal / closed socket) --------------->|
     |<-------- [RST, ACK] Connection Reset --------------------| (RST=1, ACK=1)
```

Wireshark GUI 3-Pane Structure:
```
+-----------------------------------------------------------------------------+
| Top Pane: Packet List (No., Time, Source IP, Dest IP, Protocol, Length, Info) |
+-----------------------------------------------------------------------------+
| Middle Pane: Packet Details (Frame -> Ethernet -> IPv4 -> TCP -> TLS/HTTP)   |
+-----------------------------------------------------------------------------+
| Bottom Pane: Packet Bytes (Hexadecimal offset dump and ASCII representation) |
+-----------------------------------------------------------------------------+
```

7. FILTER EXPRESSIONS CHEAT SHEET
--------------------------------------------------------------------------------
Filter Category     Filter Expression                          Description
-------------------------------------------------------------------------------------------------
Capture Filter      `host 157.240.22.35`                       Capture only packets to/from specific IP
Capture Filter      `tcp port 443`                             Capture only HTTPS TLS traffic
Capture Filter      `tcp port 80`                              Capture only unencrypted HTTP traffic
Capture Filter      `host facebook.com`                        Resolves domain and captures for that IP
Display Filter      `tcp`                                      Displays all TCP segments
Display Filter      `http`                                     Displays all unencrypted HTTP packets
Display Filter      `tls` or `ssl`                             Displays all TLS encrypted handshakes
Display Filter      `ip.addr == 157.240.22.35`                 Shows all packets where IP is src or dst
Display Filter      `tcp.flags.syn == 1 && tcp.flags.ack == 0` Shows only initial SYN request packets
Display Filter      `tcp.flags.syn == 1 && tcp.flags.ack == 1` Shows SYN-ACK reply packets
Display Filter      `tcp.flags.push == 1`                      Shows packets with Push flag active
Display Filter      `tcp.flags.reset == 1`                     Shows connection Reset packets
Display Filter      `tcp.flags.fin == 1`                       Shows connection Finish packets
Display Filter      `http.request.method == "GET"`             Shows HTTP GET requests
Display Filter      `tls.handshake.extensions_server_name`     Extracts TLS SNI domain name

8. STEP-BY-STEP PROCEDURE
--------------------------------------------------------------------------------
Step 1: Determine the Target Host IP Address
Before starting, find the IP address of the target web server (e.g., Facebook):
Open your terminal and run:
```bash
nslookup facebook.com
```
Or:
```bash
ping -c 1 facebook.com
```
- Example resolved IP: `157.240.22.35` (Meta public IPv4 edge address).

Step 2: Launch Wireshark and Select Network Interface
1. Launch Wireshark from your applications menu or terminal (`wireshark &`).
2. The welcome screen lists available network interfaces (e.g., `eth0`, `en0`, `Wi-Fi`, `Loopback`).
3. Identify your active interface showing continuous sparkline traffic activity.

Step 3: Apply Berkeley Packet Filter (BPF) Capture Filter
1. In the "...using this filter:" input box on the welcome screen, enter:
   `host 157.240.22.35`
   (Or: `tcp port 443 or tcp port 80` if targeting all web traffic).
2. Double-click your active interface to begin live capture.
3. Observe that Wireshark begins listening and buffering packets matching the filter.

Step 4: Generate Network Traffic in Web Browser
1. Open your web browser (Chrome or Firefox).
2. For maximum privacy during the experiment, open an Incognito / Private window.
3. Navigate to `https://www.facebook.com` (or your chosen lab website).
4. Perform an action (e.g. load landing page, type login credentials).
5. Once the page has loaded, return to Wireshark.

Step 5: Stop the Packet Capture
1. Click the red square "Stop Capture" button on the top toolbar.
2. Select File -> Save As... and save your capture as `facebook_capture.pcapng`.

Step 6: Apply Display Filters and Count TCP Flags
Now isolate and analyze specific packet types using the top Display Filter bar:

1. View all TCP traffic with the target:
   Filter: `tcp && ip.addr == 157.240.22.35`
   Observe the bottom status bar: `Packets: <Displayed> | Displayed: <X> (<Y>%)`.
   Record the total displayed TCP packet count.

2. Isolate and Count TCP SYN Packets (Handshakes):
   Filter: `tcp.flags.syn == 1 && ip.addr == 157.240.22.35`
   Press Enter.
   Look at the Packet Details pane -> expand "Transmission Control Protocol" -> expand "Flags".
   Observe: `.... ..0. .... = Syn: Set`.
   Record the number of SYN packets in the status bar.

3. Isolate and Count TCP PSH Packets (Data delivery):
   Filter: `tcp.flags.push == 1 && ip.addr == 157.240.22.35`
   Press Enter.
   Observe: `.... .1.. .... = Push: Set`.
   Record the number of PSH packets.

4. Isolate and Count TCP RST Packets (Abrupt terminations):
   Filter: `tcp.flags.reset == 1 && ip.addr == 157.240.22.35`
   Press Enter.
   Observe if any connections were rejected or terminated with RST.
   Record the number of RST packets.

5. Inspect HTTP vs. TLS Protocols:
   Filter: `http && ip.addr == 157.240.22.35`
   If targeting Facebook over standard HTTPS, plain HTTP filter may return 0 packets because traffic is encrypted TLS.
   Now filter: `tls && ip.addr == 157.240.22.35`
   Observe the TLS Client Hello and Server Hello handshakes.
   Expand "Transport Layer Security" -> "Extension: server_name" to verify the target domain `facebook.com`.

Step 7: Analyze Conversations and Compute Traffic Fractions
1. Click Statistics -> Conversations from the top menu.
2. Select the "IPv4" and "TCP" tabs.
3. Find the conversation between your local machine IP and the target server IP.
4. Compute the statistics:
   - Total TCP Packets = T
   - SYN Packets = S -> Fraction = S / T
   - PSH Packets = P -> Fraction = P / T
   - RST Packets = R -> Fraction = R / T
   - HTTP/TLS Packets = H -> Fraction = H / T

10. COMMON ERRORS AND TROUBLESHOOTING
--------------------------------------------------------------------------------
1. Problem: "No interfaces found" or "You don't have permission to capture on these devices".
   Cause: Wireshark lacks root or raw socket capabilities on Linux.
   Fix: Run `sudo usermod -aG wireshark $USER`, followed by `sudo chmod +x /usr/bin/dumpcap`. Log out and log back in. On macOS, run `/Library/Application Support/Wireshark/ChmodBPF/ChmodBPF`.
2. Problem: Display filter `http` shows zero packets for Facebook.
   Cause: Facebook exclusively uses TLS/HTTPS (Port 443). Plain HTTP is not used.
   Fix: Use display filter `tls` or `tcp.port == 443`.
3. Problem: Capture file is enormous (hundreds of megabytes).
   Cause: No capture filter was applied, recording all background system downloads, Spotify, Zoom, and operating system telemetry.
   Fix: Always apply a restrictive BPF capture filter (`host <target-ip>`) before starting live capture.

12. VIVA QUESTIONS WITH CONCISE, CORRECT ANSWERS
--------------------------------------------------------------------------------
Q1: What is the fundamental difference between a Capture Filter and a Display Filter?
A: A Capture Filter (BPF syntax) discards non-matching packets in the kernel before saving, whereas a Display Filter (Wireshark syntax) filters already captured packets without deleting them.

Q2: What is the Berkeley Packet Filter (BPF) syntax to capture traffic to a specific IP?
A: `host <IP-address>` (e.g. `host 157.240.22.35`).

Q3: What does the TCP SYN flag indicate?
A: Synchronize sequence numbers; it is set in the first two segments of the TCP 3-way handshake to establish a connection.

Q4: What does the TCP PSH flag indicate?
A: Push; it instructs the receiver's TCP stack to immediately deliver buffered data to the application layer without waiting for full buffers.

Q5: What does the TCP RST flag indicate?
A: Reset; it terminates an invalid connection abnormally or rejects an incoming segment on an unopened port.

Q6: What is the 3-way handshake sequence in Wireshark?
A: Packet 1: `[SYN]`, Packet 2: `[SYN, ACK]`, Packet 3: `[ACK]`.

Q7: What display filter isolates all packets with the SYN flag enabled?
A: `tcp.flags.syn == 1`.

Q8: What display filter isolates all packets where the SYN flag is set but ACK is NOT set?
A: `tcp.flags.syn == 1 && tcp.flags.ack == 0` (initial connection requests).

Q9: Why does Wireshark display relative sequence numbers by default?
A: To simplify analysis by starting sequence numbers at 0 rather than large random 32-bit integers.

Q10: Why does searching for `http` traffic on modern Facebook yield few or no packets?
A: Facebook uses HTTPS (TLS Port 443) exclusively, which encrypts HTTP requests and responses into TLS records.

Q11: Where can the target website domain be seen in an encrypted HTTPS capture?
A: In the unencrypted `TLS Client Hello` packet under the Server Name Indication (SNI) extension.

Q12: What does the `ip.addr == x.x.x.x` display filter do?
A: It matches packets where `x.x.x.x` appears as either the source IP or destination IP.

Q13: How can you inspect overall traffic statistics for an IP in Wireshark?
A: Through `Statistics -> Conversations` or `Statistics -> Endpoints`.

Q14: What file format does Wireshark use by default for saving captures?
A: `.pcapng` (Packet Capture Next Generation).

Q15: What library powers packet capturing under Linux and macOS?
A: `libpcap` (or `Npcap` / `WinPcap` on Windows).

14. QUICK REVISION POINTS
--------------------------------------------------------------------------------
- Capture Filter: BPF syntax (`host x.x.x.x`), set *before* capture; permanently excludes non-matching packets.
- Display Filter: Wireshark syntax (`ip.addr == x.x.x.x`), set *after* capture; reversible view filter.
- Handshake: SYN -> SYN-ACK -> ACK.
- Flags: SYN (connect), PSH (push data), RST (reset), FIN (teardown), ACK (acknowledge).
- Filter flags: `tcp.flags.syn == 1`, `tcp.flags.push == 1`, `tcp.flags.reset == 1`.
- HTTPS Reality: Facebook uses TLS (port 443); metadata and TCP headers are clear, payload is encrypted.
