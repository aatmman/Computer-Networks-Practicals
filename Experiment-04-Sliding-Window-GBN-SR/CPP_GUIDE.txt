5. THEORY AND IMPORTANT TERMINOLOGY
--------------------------------------------------------------------------------
- Sliding Window Protocol: A flow control and reliable transmission technique that allows the sender to transmit multiple data frames (up to window size N) without waiting for an acknowledgment (ACK) for each individual frame, overcoming the low throughput of Stop-and-Wait.
- Sender Window: The range of consecutive sequence numbers that the sender is authorized to transmit without receiving an ACK. As acknowledgments arrive, the window "slides" forward over higher sequence numbers.
- Go-Back-N (GBN) ARQ:
  * Cumulative Acknowledgments: An ACK for frame n (ACK n) implies all frames up to and including n have been successfully received.
  * Receiver Window Size = 1: The receiver accepts frames only in strict sequential order. If an out-of-order frame arrives (due to a preceding lost or damaged frame), the receiver discards it immediately without buffering.
  * Retransmission: On sender timeout for frame k, the sender must roll back and retransmit frame k and ALL subsequent frames currently outstanding in the window, even if those subsequent frames originally reached the receiver intact.
- Selective Repeat (SR) ARQ:
  * Individual Acknowledgments: Each frame is acknowledged individually.
  * Receiver Window Size = N: The receiver possesses an internal buffer capable of storing up to N out-of-order but uncorrupted frames.
  * Retransmission: On sender timeout for frame k, the sender retransmits ONLY frame k. Correctly received out-of-order frames are retained in the receiver's buffer, avoiding redundant retransmissions.
- Sequence Number Constraints:
  * If sequence numbers use m bits (range 0 to 2^m - 1):
  * GBN maximum window size is 2^m - 1 to prevent ambiguity between duplicate ACKs of consecutive cycles.
  * SR maximum window size is 2^(m - 1) to ensure the sender window and receiver window never overlap across modular sequence numbering cycles.

6. WORKING PRINCIPLE / ALGORITHM
--------------------------------------------------------------------------------
Go-Back-N Algorithm:
1. Initialize `base = 0`, `windowSize = N`, `totalFrames = M`.
2. While `base < totalFrames`:
   a. Compute active window bounds: `[base .. min(base + N, totalFrames) - 1]`.
   b. Transmit all frames in the window.
   c. If a frame `lostFrame` within the window is simulated as lost:
      - The receiver receives and drops `lostFrame`.
      - For all subsequent frames in this window pass, the receiver discards them as out-of-order.
      - Sender timer expires for `lostFrame`.
      - Count retransmissions: `retransmissions += (windowEnd - lostFrame)`.
      - Roll back sender `base` to `lostFrame`.
      - Mark loss handled (`lostFrame = -1`) so the next pass delivers cleanly.
   d. If no loss in the window:
      - All frames acknowledged cumulatively.
      - Slide window forward: `base = windowEnd`.

Selective Repeat Algorithm:
1. Initialize `base = 0`, boolean arrays `acked[totalFrames]` and `receiverBuffered[totalFrames]`.
2. While `base < totalFrames`:
   a. Compute active window bounds: `[base .. min(base + N, totalFrames) - 1]`.
   b. Transmit all unacknowledged frames in the window.
   c. If a frame `lostFrame` within the window is dropped:
      - Frames arriving after `lostFrame` are buffered by the receiver and individually acknowledged (`acked[i] = true`).
      - Sender timer expires solely for `lostFrame`.
      - Retransmit ONLY `lostFrame`: `retransmissions += 1`.
      - Mark `acked[lostFrame] = true` and `lostFrame = -1`.
   d. Slide window forward: advance `base` past all consecutively acknowledged frames.

--- File: go_back_n.cpp ---
```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

int main() {
    cout << "========================================================\n";
    cout << "    GO-BACK-N (GBN) SLIDING WINDOW ARQ SIMULATION - C++ \n";
    cout << "========================================================\n";

    int totalFrames, windowSize, lostFrame;
    cout << "Enter total number of frames to send: ";
    if (!(cin >> totalFrames) || totalFrames <= 0) {
        cerr << "Error: Total frames must be a positive integer.\n";
        return 1;
    }

    cout << "Enter sliding window size (N): ";
    if (!(cin >> windowSize) || windowSize <= 0) {
        cerr << "Error: Window size must be a positive integer.\n";
        return 1;
    }

    cout << "Enter frame index to simulate as LOST (0-indexed, or -1 for none): ";
    cin >> lostFrame;

    int base = 0;
    int retransmissions = 0;
    int passNumber = 1;

    cout << "\nStarting Go-Back-N Simulation...\n";
    cout << "Window Size (N) = " << windowSize << ", Total Frames = " << totalFrames << "\n";

    while (base < totalFrames) {
        int windowEnd = min(base + windowSize, totalFrames);
        cout << "\n[Pass " << passNumber++ << "] Active Window: [" << base << " .. " << windowEnd - 1 << "]\n";
        cout << "  Sender transmitting frames " << base << " through " << windowEnd - 1 << "...\n";

        bool lossOccurred = false;
        int firstLostInThisPass = -1;

        for (int i = base; i < windowEnd; i++) {
            if (i == lostFrame) {
                cout << "    -> Frame " << i << " : [DROPPED / LOST IN TRANSIT]\n";
                lossOccurred = true;
                firstLostInThisPass = i;
                // In Go-Back-N, receiver discards all subsequent out-of-order frames
                for (int j = i + 1; j < windowEnd; j++) {
                    cout << "    -> Frame " << j << " : [ARRIVED OUT-OF-ORDER - DISCARDED BY RECEIVER]\n";
                }
                break;
            } else {
                cout << "    -> Frame " << i << " : [RECEIVED & CUMULATIVE ACK SENT]\n";
            }
        }

        if (lossOccurred) {
            cout << "  [TIMEOUT] Timer expired for unacknowledged Frame " << firstLostInThisPass << "!\n";
            cout << "  [GO-BACK-N ACTION] Sender rolls window back to Frame " << firstLostInThisPass << ".\n";
            int framesToRetransmit = windowEnd - firstLostInThisPass;
            cout << "  Retransmitting " << framesToRetransmit << " frame(s): ";
            for (int r = firstLostInThisPass; r < windowEnd; r++) {
                cout << r << (r == windowEnd - 1 ? "" : ", ");
            }
            cout << "\n";
            retransmissions += framesToRetransmit;

            // Reset lostFrame so it successfully delivers upon retransmission
            lostFrame = -1;
            // Roll back sender base to the lost frame
            base = firstLostInThisPass;
        } else {
            cout << "  All frames in window [" << base << " .. " << windowEnd - 1 << "] acknowledged successfully.\n";
            base = windowEnd; // Slide window forward
        }
    }

    cout << "\n========================================================\n";
    cout << "SIMULATION COMPLETE\n";
    cout << "Total Frames Successfully Transmitted : " << totalFrames << "\n";
    cout << "Total Retransmissions in Go-Back-N     : " << retransmissions << "\n";
    cout << "Total Frame Transmissions (Original+Retx): " << totalFrames + retransmissions << "\n";
    cout << "========================================================\n";

    return 0;
}
```

--- File: selective_repeat.cpp ---
```cpp
#include <iostream>
#include <vector>
#include <set>
#include <algorithm>

using namespace std;

int main() {
    cout << "========================================================\n";
    cout << "  SELECTIVE REPEAT (SR) SLIDING WINDOW ARQ SIMULATION - C++\n";
    cout << "========================================================\n";

    int totalFrames, windowSize, lostFrame;
    cout << "Enter total number of frames to send: ";
    if (!(cin >> totalFrames) || totalFrames <= 0) {
        cerr << "Error: Total frames must be a positive integer.\n";
        return 1;
    }

    cout << "Enter sliding window size (N): ";
    if (!(cin >> windowSize) || windowSize <= 0) {
        cerr << "Error: Window size must be a positive integer.\n";
        return 1;
    }

    cout << "Enter frame index to simulate as LOST (0-indexed, or -1 for none): ";
    cin >> lostFrame;

    vector<bool> acked(totalFrames, false);
    vector<bool> receiverBuffered(totalFrames, false);
    int retransmissions = 0;
    int base = 0;
    int passNumber = 1;

    cout << "\nStarting Selective Repeat Simulation...\n";
    cout << "Window Size (N) = " << windowSize << ", Total Frames = " << totalFrames << "\n";

    while (base < totalFrames) {
        int windowEnd = min(base + windowSize, totalFrames);
        cout << "\n[Pass " << passNumber++ << "] Active Window: [" << base << " .. " << windowEnd - 1 << "]\n";
        cout << "  Sender transmitting unacknowledged frames in window...\n";

        bool lossOccurred = false;

        for (int i = base; i < windowEnd; i++) {
            if (acked[i]) {
                cout << "    -> Frame " << i << " : [ALREADY ACKNOWLEDGED - SKIPPED]\n";
                continue;
            }

            if (i == lostFrame) {
                cout << "    -> Frame " << i << " : [DROPPED / LOST IN TRANSIT]\n";
                lossOccurred = true;
            } else {
                acked[i] = true;
                receiverBuffered[i] = true;
                cout << "    -> Frame " << i << " : [RECEIVED & BUFFERED OUT-OF-ORDER BY RECEIVER -> INDIVIDUAL ACK SENT]\n";
            }
        }

        if (lossOccurred) {
            cout << "  [TIMEOUT] Timer expired ONLY for unacknowledged Frame " << lostFrame << "!\n";
            cout << "  [SELECTIVE REPEAT ACTION] Retransmitting ONLY Frame " << lostFrame << "...\n";
            cout << "    -> Frame " << lostFrame << " : [RETRANSMITTED SUCCESSFULLY -> ACK RECEIVED]\n";
            acked[lostFrame] = true;
            receiverBuffered[lostFrame] = true;
            retransmissions++;
            lostFrame = -1; // Loss handled
        }

        // Slide the window forward past all consecutively acknowledged frames
        int oldBase = base;
        while (base < totalFrames && acked[base]) {
            base++;
        }
        cout << "  Receiver delivered in-order frames up to " << base - 1 << ".\n";
        cout << "  Window slid forward by " << (base - oldBase) << " position(s). New base = " << base << "\n";
    }

    cout << "\n========================================================\n";
    cout << "SIMULATION COMPLETE\n";
    cout << "Total Frames Successfully Transmitted : " << totalFrames << "\n";
    cout << "Total Retransmissions in Selective Repeat : " << retransmissions << "\n";
    cout << "Total Frame Transmissions (Original+Retx): " << totalFrames + retransmissions << "\n";
    cout << "========================================================\n";

    return 0;
}
```

9. EXPLANATION OF THE CODE
--------------------------------------------------------------------------------
- In `go_back_n.cpp`:
  * `base`: Points to the lowest unacknowledged frame index.
  * When `i == lostFrame`, subsequent frames in that pass are explicitly noted as discarded by the receiver, accurately simulating receiver window size = 1.
  * On timeout, `base` is rolled back to `firstLostInThisPass`, and the sender re-executes transmission from that frame forward.
- In `selective_repeat.cpp`:
  * `vector<bool> acked` and `vector<bool> receiverBuffered`: Track individual frame reception and out-of-order buffering at the receiver.
  * When `lostFrame` fails, frames transmitted after it are individually acknowledged and stored in `receiverBuffered`.
  * Retransmission targets strictly `lostFrame` (`retransmissions++`), leaving already ACKed frames undisturbed.
  * The window slides forward past all consecutive ACKs using `while (base < totalFrames && acked[base]) base++`.

16. MANUAL CODE NOTE / CORRECTION / ENHANCEMENT
--------------------------------------------------------------------------------
- CRITICAL LAB MANUAL BUG NOTE:
  In the official lab manual's sample code for `go_back_n.cpp`, the rollback logic contained contradictory statements:
  ```cpp
  base = lostFrame;    // placeholder, corrected below
  base = base;         // (kept for clarity of GBN restart point)
  base = windowEnd - (windowEnd - lostFrame >= 0 ? 0 : 0);
  base = windowEnd;    // <-- BUG: unconditionally advances base, skipping retransmission!
  ```
  Because `base = windowEnd;` was executed unconditionally at the end of the loop, the manual's sample code never actually rolled back to retransmit the lost frames in the subsequent iteration!
  In our corrected code, when a loss occurs, `base` is correctly rolled back to `firstLostInThisPass`, and window sliding (`base = windowEnd`) only executes when all frames in the window have been acknowledged without loss.

17. VIVA QUESTIONS WITH CONCISE, CORRECT ANSWERS
--------------------------------------------------------------------------------
Q1: What is the main operational difference between Go-Back-N and Selective Repeat?
A: GBN discards out-of-order frames and retransmits all frames from the lost frame onward; SR buffers out-of-order frames and retransmits only the lost frame.

Q2: What is the receiver window size in Go-Back-N?
A: Exactly 1. The receiver only accepts the expected sequence number.

Q3: What is the receiver window size in Selective Repeat?
A: Equal to the sender window size N (up to 2^(m - 1)).

Q4: What type of acknowledgment does Go-Back-N use?
A: Cumulative ACKs, where ACK n confirms receipt of all frames up to n.

Q5: What type of acknowledgment does Selective Repeat use?
A: Individual ACKs (or Selective ACKs / SACK), acknowledging each received frame separately.

Q6: For an m-bit sequence number space, what is the maximum window size in Go-Back-N?
A: 2^m - 1.

Q7: For an m-bit sequence number space, what is the maximum window size in Selective Repeat?
A: 2^(m - 1) (half the sequence number space).

Q8: Why can't the window size in Selective Repeat exceed 2^(m - 1)?
A: To prevent overlapping between the current receiver window and the next cycle's sender window, which would cause duplicate frames to be mistaken for new frames.

Q9: What happens in Go-Back-N if an intermediate ACK is lost in transit?
A: If a subsequent ACK arrives (e.g., ACK 3 after ACK 2 is lost), cumulative acknowledgment automatically covers the earlier frames without triggering retransmission.

Q10: Which protocol requires more memory buffers at the receiver?
A: Selective Repeat, because it must store out-of-order frames until missing frames arrive to deliver them in sequence.

Q11: Under what network condition is Go-Back-N acceptable despite its inefficiency?
A: On links with very low error rates and small propagation delays, where retransmissions are rare and protocol simplicity is prioritized.

Q12: Under what condition is Selective Repeat clearly superior?
A: On high-latency, high-bandwidth-delay product links with noisy channels (e.g., satellite links), where retransmitting entire windows wastes substantial bandwidth.

Q13: What triggers frame retransmission in both protocols?
A: Expiration of a retransmission timer associated with an unacknowledged frame.

Q14: How does TCP implement sliding window reliability?
A: Modern TCP uses a hybrid: cumulative ACKs with Selective Acknowledgment (SACK, RFC 2018) similar to Selective Repeat.

Q15: What is piggybacking in sliding window protocols?
A: Temporarily delaying an outgoing ACK so it can be combined with outgoing data payload in a single frame.

19. QUICK REVISION POINTS
--------------------------------------------------------------------------------
- GBN: Receiver window = 1; cumulative ACK; discards out-of-order; retransmits N frames; Max N = 2^m - 1.
- SR: Receiver window = N; individual ACK; buffers out-of-order; retransmits 1 frame; Max N = 2^(m - 1).
- Efficiency: SR uses fewer retransmissions and less bandwidth over noisy links.
- Complexity: SR requires receiver sorting/buffering and per-frame timers.
